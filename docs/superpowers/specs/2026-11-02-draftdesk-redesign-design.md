# DraftDesk 재설계 — 설계 문서

작성일: 2026-11-02 · 상태: 사용자 검토 대기

## 1. 왜 만드나 (의도)

사용자의 아버지는 환갑이 넘은 공조 설치 기사다. 고객이 PDF나 이미지로 보낸 도면 위에 설치할 공조·배관을 그려 넣어 다시 고객에게 보낸다. 시중 PDF 편집 프로그램은 유료이고 너무 복잡해서, 사용자가 아버지 한 사람을 위해 직접 만든다.

기존 DraftDesk(React)는 사용자 본인 기준으로는 쓸 만하지만 아버지는 어려워한다. 기능을 늘리는 것이 아니라 **아버지가 헷갈리지 않게 새로 설계**하는 것이 이번 작업의 목적이다. 기존 코드는 참고만 하고 처음부터 새로 만든다.

## 2. 사용자와 환경

- 사용자: 환갑 이상, 노안, 기계 사용이 서툼. 윈도우 노트북 + **마우스**. 태블릿 없음.
- 도면: 카톡·메일·문자로 받음. **PDF가 대부분**, 10장 넘는 것도 있음. 이미지(사진·캡처)는 가끔.
- 한 번 작업은 짧다. 도형 몇 개 넣고 저장하는 정도. 하루 이틀 걸쳐 하지 않는다.

## 3. 목표 / 비목표 / 안티 목표

**목표**
- 아버지 혼자, 설명 없이 도면을 열고 그리고 저장할 수 있다.
- 글씨·버튼이 매우 크다.
- 등록(그리기), 수정(옮기기·크기·색), 삭제만 확실히 된다.

**비목표 (이번에 만들지 않는다)**
- PDF 합치기, 분리, 페이지 회전·삭제·순서 변경
- 로그인, 서버, 계정
- 작업 중 임시 저장 / 이어서 하기
- 글씨 목록 내보내기·불러오기
- 되돌리기(Undo)는 요구되지 않았다. 필요하다고 판단되면 빌더가 제안할 수 있으나 기본 범위가 아니다.

**안티 목표 (기능은 되지만 실패인 경우)**
- 아버지가 버튼 용도를 몰라 멈추는 화면
- 작은 글씨, 얇은 선, 작은 클릭 영역
- 저장했는데 파일이 어디 갔는지 모르는 상태
- 페이지를 넘겼더니 그린 것이 사라지는 동작(기존 앱의 문제)

## 4. 결정된 것 (사용자가 정함)

### 4.1 화면 구성 — A안(위쪽 큰 버튼 줄)
- 위쪽 한 줄에 큰 버튼: **도면 열기 / 공조 / 배관(직선) / 배관(꺾기) / 글씨 / 저장**
- 가운데는 도면이 화면 대부분을 차지한다.
- 아래쪽에 "◀ 이전 장 3 / 12 다음 장 ▶"를 크게 표시한다.
- 시안: `.superpowers/brainstorm/396-1793578677/content/layout.html`

### 4.2 도면 열기
- 큰 "도면 열기" 버튼 + 파일을 화면에 끌어다 놓기. PDF와 이미지(PNG/JPG) 지원.

### 4.3 그리기 (마우스로 끌어서)
- **공조**: 직사각형·정사각형. 끌어서 크기를 정한다. **안을 고른 색으로 가득 채운다**(사용자 요청, 2026-11-02).
- **배관(직선)**: 굵은 직선.
- **배관(꺾기)**: 시작점에서 끝점까지 끌면 가로-세로로 꺾인 ㄱ·ㄴ자가 자동으로 그려진다. 꺾이는 배관이 직선보다 많다. 꺾이는 방향이 반대면 선택 후 "방향 바꾸기"로 뒤집는다.
- **색**: 공조·배관 모두 기본 **8색 팔레트**에서 고른다. 도면이 검정·회색이므로 도면과 구분되는 색 위주. 거창한 색 선택기는 두지 않는다.

### 4.4 글씨
- 글씨를 하나 놓으면 도구가 선택으로 돌아가고 그 글씨가 선택된다(옮기기·색·크기·지우기가 바로 가능, 사용자 요청). 또 붙이려면 글씨 버튼을 다시 누른다.
- 글씨 버튼을 누르면 위쪽에 지금까지 입력한 말이 큰 버튼으로 나열된다. 버튼을 누르고 도면을 클릭하면 붙는다.
- 목록에 없는 말은 "직접 입력"하면 붙고 목록에 자동 추가된다. 잘못 입력한 말은 목록에서 지울 수 있다.
- 저장소: **브라우저(localStorage)**. 서버 없음. 브라우저 기록을 지우면 목록도 사라지는 것은 감수한다.
- 기본 말 16개를 미리 넣어 둔다(사용자 승인): 덕트, 2웨이, 4웨이, 환기구, 급기, 배기, 에어컨, 실외기, 냉매관, 배수관, 드레인, 보온, 상향, 하향, 천장, 벽체.

### 4.5 수정·삭제
- 그린 것을 클릭하면 선택된다. 선택 시 옮기기, 크기 조절, 색 바꾸기, 지우기가 가능하다. 지우기는 큰 버튼으로 나타난다.

### 4.6 여러 페이지
- 페이지를 넘겨도 그린 내용은 유지된다. 페이지별로 그림을 따로 보관한다.

### 4.7 확대
- "＋ 크게 / － 작게" 큰 버튼, 최대 약 400%. 마우스 휠도 보조로 지원. 확대 상태에서는 끌어서 이동한다. 처음 열 때는 화면 너비에 맞춘다.
- 노안 때문에 글씨가 "매우 커야 한다"가 핵심 요구다.

### 4.8 저장
- 저장 버튼을 누르면 큰 선택 창이 뜬다. 먼저 **범위**를 고르고, 범위가 "한 장"일 때만 **형식** 분기가 생긴다.
  - **범위 1) 전체 페이지**(처음 선택): 결과는 PDF 하나. 형식 선택 없음.
  - **범위 2) 수정한 페이지만**("(3장)"처럼 장 수 표시): 수정한 페이지들만 모은 PDF 하나. 형식 선택 없음.
  - **범위 3) 지금 보는 한 장만**: 여기서만 **형식을 고른다 — PDF / 이미지(PNG)**. 화면에 "지금 보는 3장이 저장됩니다"를 알려 준다.
  - 즉 여러 장을 저장하면 항상 PDF, 한 장을 저장할 때만 PDF 또는 이미지를 고른다.
  - 이미지 도면을 열었을 때는 한 장이므로 범위 선택 없이 형식(PDF / 이미지)만 고른다.
- 파일은 브라우저 기본 다운로드 폴더로 간다. 이름은 원본 이름 + `_편집` (예: `3층도면_편집.pdf`). 원본은 덮어쓰지 않는다.
- 저장이 끝나면 파일 이름과 "다운로드 폴더에 저장했습니다"를 크게 보여 준다.

### 4.9 기술 방식
- **Vue 3 + JavaScript, 서버 없음**, 기존 GitHub Pages에 배포한다(기존 `npm run deploy` 흐름 유지 가능).
- Python은 쓰지 않는다. 사용자는 "PDF에 더 용이해서" 원했으나, 서버가 없고 이 앱의 핵심(그리기·저장)은 JS가 더 가볍기 때문에 JS로 한다. 사용자는 JS로 해도 상관없다고 했다.

## 5. 설계자(Claude)의 결정 — 사용자 확인 필요

- 임시 저장(이어서 하기)은 뺀다.
- 화면 글씨: 버튼 글씨 20px 이상, 선택 클릭 영역도 크게.
- 도면에 쓰는 글씨의 기본 크기는 크게(인쇄해도 읽히는 정도).
- 배관 꺾임은 **한 번만** 꺾이는 것으로 가정한다(여러 번 꺾이는 경우는 아직 확인되지 않음).
- 8색 팔레트의 구체적인 색은 빌더가 고른다. 마지막에 고른 색은 기억한다.
- 마지막 선택 색 기억도 localStorage를 쓴다.

### 5.1 검토자 질문에 대한 설계자의 결정 (사용자 확인 필요)

- **"수정한 페이지"**: 지금 도형·글씨가 하나라도 올라 있는 페이지. 그렸다가 전부 지워 원래대로 돌아가면 수정한 페이지가 아니다. "(N장)" 표시도 같은 기준이다.
- **원본 PDF 유지**: 저장된 PDF에서 원본 페이지는 벡터·텍스트 그대로 두고 그 위에 도형·글씨를 얹는다(기존 PDF를 편집할 수 있는 라이브러리 사용). 이미지 도면은 원본 해상도 그대로 한 페이지 PDF로 만든다. 한글 글씨는 한글 폰트를 파일에 임베드하는 쪽을 우선 검토하고, 번들 크기·라이선스 때문에 어려우면 이미지로 넣는 것도 허용(빌더 판단).
- **좌표**: 도형은 각 페이지의 PDF 좌표계로 저장하고 화면에는 캔버스나 SVG 오버레이로 그린다. 크기가 다르거나 회전된 페이지도 화면과 저장 결과가 일치해야 한다.
- **저장 창 중복 선택지**: 한 장짜리 PDF나 이미지 도면이면 의미가 겹치는 범위 선택은 숨기고 형식(PDF / 이미지)만 보여 준다.
- **저장 안 한 작업 보호**: 그린 것이 있는 상태에서 새 도면을 열거나 탭을 닫으려 하면 큰 확인 창("저장하지 않은 작업이 있습니다. 그래도 새로 열까요?")을 띄운다. 임시 저장은 여전히 하지 않는다.
- **배관(꺾기)**: 기본은 가로로 먼저 갔다가 세로로 꺾인다. "방향 바꾸기" 버튼은 배관을 선택하면 나타나는 큰 버튼 줄(지우기, 색 바꾸기와 같은 줄)에 둔다. 선택하면 양 끝점에 손잡이가 생겨 끝점을 끌면 꺾임 모양이 자동으로 따라간다. 데이터는 "두 끝점 + 방향 플래그"로 가정한다.
- **글씨**: 공조·배관과 같은 객체처럼 옮기기, 색 바꾸기(같은 8색), 지우기가 된다. 크기는 선택 후 "글씨 크게 / 작게" 큰 버튼으로 조절한다. 붙일 때는 클릭한 지점이 글씨 왼쪽 위가 된다.
- **마우스 끌기 구분**: 그리기 도구(공조·배관·글씨)가 켜져 있으면 끌기는 그리기. 도구가 꺼진 기본 상태에서 도형 위를 끌면 옮기기, 빈 곳을 끌면 화면 이동. 별도의 손 도구 버튼은 두지 않는다.
- **도구 유지**: 도형 하나를 놓으면 기본 상태(선택)로 돌아간다. 켜진 도구는 버튼이 진하게 표시된다.
- **화면 크기**: 1280×720 정도의 노트북 화면(Windows 배율 125~150%)에서도 위쪽 버튼 줄이 한 줄로 들어가야 한다. 글씨 목록은 줄바꿈하거나 스크롤한다.
- **성능**: 페이지는 보고 있는 것만 그린다(필요할 때 렌더링). 저장 중에는 "저장 중…" 표시를 크게 보여 준다.
- **배포 환경**: Chrome/Edge로 GitHub Pages 주소를 연다고 가정한다. PDF 렌더링 워커와 폰트는 CDN이 아니라 번들에 포함한다(네트워크가 불안정해도 열리게).
- **저장 파일 이름 충돌**: 브라우저가 붙이는 "(1)" 때문에 화면에 보인 이름과 실제 이름이 다를 수 있음을 알려 준다("같은 이름이 있으면 (1)이 붙을 수 있습니다"). 별도 번호나 시각은 붙이지 않는다.

## 6. 빌더에게 맡기는 것

- 프로젝트 구조, 상태 관리 방식(Pinia 등), 빌드 설정, PDF 라이브러리 선택(렌더링·저장)
- 한글 글씨가 PDF에 들어갈 때의 처리(텍스트를 이미지로 넣을지, 한글 폰트를 임베드할지). 기존 앱은 canvas PNG로 넣어 텍스트 검색·선택이 안 되었다. 더 나은 방법이 있으면 선택해도 좋다.
- 정확한 색 값, 아이콘, 크기 수치
- 테스트 전략

## 7. 알려진 제약

- 파일이 서버로 가지 않는다. 모든 처리는 브라우저 안에서 한다.
- 글씨 목록과 마지막 색은 그 노트북·그 브라우저에만 저장된다.
